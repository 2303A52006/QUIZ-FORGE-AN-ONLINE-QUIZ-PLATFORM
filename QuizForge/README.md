# QuizForge | Department learning studio

A Django application, not a mock-up. Teachers author assessments; students take timed, auto-marked quizzes. SQLite stores accounts, questions, answer choices, deadlines, answers and grades. Both dashboards use live database records.

## Assumptions
- Pass marks are percentages; each question is worth one mark.
- Published quizzes are immutable. Duplicate one to revise it.
- Dashboard rank refers to the student's most recently finished quiz.
- The builder and dates shown in the interface use India Standard Time.
- Demo credentials are generated locally rather than hard-coded.

## Windows: first run
Install Python 3.12 or 3.13 (including the Python launcher) and VS Code. Extract the ZIP, open the **QuizForge** folder containing `manage.py` in VS Code, and open Terminal → New Terminal → PowerShell. Run these lines in order. With Python 3.13 installed instead, change `-3.12` to `-3.13`.

```powershell
py -3.12 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:QUIZFORGE_SECRET = python -c "import secrets; print(secrets.token_urlsafe(64))"
$env:DEBUG = '1'
python manage.py makemigrations
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```
Open **http://127.0.0.1:8000/**. Leave the terminal running. Ctrl+C stops the server. `No changes detected` is expected: the initial migration was generated by Django and is included. No database download is necessary. Bootstrap, icons, Inter, and Chart.js load from CDNs and need internet access in the browser.

**Demo logins:** `teacher`, `student01` through `student10`, and `admin` (at `/admin/`). Copy the corresponding passwords printed by `seed_demo`. Students share a demo password; the admin and teacher each have a separate password. Seed once on a fresh database; existing demo usernames are never overwritten. Use non-demo accounts and private passwords on a real department site. To create a teacher, use Django admin → Users → Add user, set a username/password, tick **Teacher**, and save. Teachers do not require staff privileges.

**Later sessions:** Activate the virtual environment again and set `DEBUG` and `QUIZFORGE_SECRET` before running commands. Reuse the same secret (store it in your password manager); changing it signs out existing sessions. Do not commit secrets. For a clean installation without samples use `createsuperuser` instead of `seed_demo`.

## Automated checks
In the configured PowerShell terminal:
```powershell
python manage.py test --verbosity 2
python manage.py check
python manage.py makemigrations --check --dry-run
```
Tests use a temporary database. They exercise server routes, draft publication/copy, role and ownership checks, negative and zero-floor scoring, skipped items, deadline truncation, late-answer rejection, expiry, attempt limits, option ID validation, stable question/option order, answer persistence, private feedback and ranking ties.

### How scoring and expiry work
Score = max(0, correct − wrong × penalty). Unanswered contributes zero. Pass comparison uses the unrounded score. Best-attempt ties use shorter elapsed time, then attempt ID for deterministic ordering. The displayed averages are the mean of best-attempt percentages, not total marks divided by total questions. Student score trends and activity volumes include retries. Topic accuracy is correct answers divided by question exposures, including skips.

The browser saves selections over CSRF-protected POST and submits at zero. The server uses its own clock on every write. A closed browser does not run a timer: on the next relevant visit (dashboard, review, export, or leaderboard), overdue attempts finalize from saved answers **as of their stored deadline**. No background scheduler is required. SQLite immediate transactions serialize start/save/finish operations. The attempt page receives choice IDs and labels but never correctness flags or explanations. An already submitted attempt has its own review, including when retakes are allowed.

## Seven-slide presentation outline
1. **QuizForge** — timed departmental assessments; show the landing screen and state the manual-marking problem.
2. **Users and scope** — admin creates teachers; teachers publish; students register, attempt and review. No classes or question bank.
3. **Architecture** — browser → Django templates/views → SQLite; session auth, CSRF, static assets and WSGI.
4. **Data model** — User → Quiz → Question → Option; Attempt links student and quiz, preserving its randomized presentation and answers.
5. **Live workflow** — draft, publish, take, refresh, submit. Demonstrate server deadline and instant review.
6. **Insights** — best-attempt leaderboard, topic accuracy, distribution and CSV. Use the weakest topic to plan revision.
7. **Verification and deployment** — test results, role isolation, deadline boundary, Windows setup and PythonAnywhere WSGI.

## Twelve viva questions
1. **Why Django?** It provides ORM, forms, authentication, CSRF middleware and admin in one stack.
2. **Why not trust the browser timer?** A user can change client time or disable JS; the server compares its own current time with the stored deadline.
3. **How is that deadline chosen?** The earlier of start plus limit and the scheduled close.
4. **How do answers survive refresh?** CSRF-protected saves persist a question-ID to option-ID map on the attempt.
5. **Why use option IDs?** A shuffled position has no stable meaning; the ID identifies the same answer in every order.
6. **How do you prevent duplicate starts?** An atomic start checks for an active attempt first, counts prior attempts and uses a unique quiz/student/number constraint.
7. **How are blank answers graded?** Neither credit nor penalty; negative totals are clamped to zero.
8. **Why use decimal scores?** Fractional penalties such as 0.25 are applied without binary floating-point grading errors.
9. **How do you protect teacher data?** Role checks plus owner-filtered database lookups on every teacher operation.
10. **How are weak topics found?** Group correct/total observations by topic using each student's best attempt per quiz.
11. **Why freeze published quizzes?** Editing the answer key after submission would invalidate historical scoring and reviews.
12. **What is SQLite's main limit here?** Writes serialize. It suits a small department demo; a larger concurrent deployment needs load testing and typically a server database.
